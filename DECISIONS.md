# Decisions

Short log of implementation decisions made without asking (per project rules).

1. **Nuxt 4.5 SPA** (`ssr: false`, `nuxt generate`, `nitro.preset: 'static'`); base path via `TELEPATTY_BASE_URL` env (default `/`). SPA fallback `404.html` written by a `nitro:build:public-assets` hook (plus workflow copy as belt-and-braces).
2. **Nuxt UI v4** + Tailwind 4. Runtime theme = `useAppConfig().ui.colors` + CSS variables (`--ui-radius`, `--tp-*`); 4 presets (Matrix, Cyber blue, Amber terminal, Stealth gray). Chat bubbles use the same tokens: the own bubble is `color-mix(accent 25%, --tp-bg)` — dark in dark mode, light in light mode, `--ui-text` on top — and the peer's is `color-mix(accent 14%, --tp-panel)`; never a hardcoded color.
3. **i18n v10** with `strategy: 'no_prefix'`, fa/en JSON in `i18n/locales`, RTL via `useLocaleHead`.
4. **Invites use the URL fragment** (`https://host/base#/add?k=<npub>&n=<name>&r=<relays>&v=1`) so no server (incl. GitHub Pages) ever sees friend data. The hash is captured client-side and rewritten to `/add?...`.
5. **Nostr only in Phase 1-3 messaging**: NIP-59 gift wrap (`createRumor` kind 14 → seal kind 13 → wrap kind 1059), JSON envelope as rumor content. NIP-40 `expiration` tag added to the wrap for relays honoring expiry. Receipts (delivered/read) are envelopes of `type: 'receipt'`.
6. **WebRTC (Phase 4) is a custom minimal layer, not Trystero**: signaling envelopes ride the Nostr transport (ephemeral-ish wrapped kind 14 rumors, `type: 'signal'`), DataChannel carries envelopes directly. Perfect-negotiation-lite (smaller pubkey initiates). Trystero would add its own swarm-keyed rooms; custom keeps one pipeline and one dedupe path.
7. **Envelope state machine**: `pending → sent → delivered → read` (+`failed`), ACK = signed receipt envelope; outbox keeps entries until delivered receipt; exponential backoff capped at 5 min, 8 attempts then `failed` with manual retry. Everything persists in Dexie (survives reload).
8. **Ordering** = per-conversation Lamport counter (bootstrapped from stored max), tie-broken by sender ts then id — clock skew safe.
9. **Dexie schema v4** with explicit migrations: v2 backfills `expireAt`, v3 adds the `lamport` index, and v4 adds local-first `conversations`, `processedEvents`, and `syncState`. Chat lists render from `conversations` only; backup import accepts v2/v3 data and rebuilds summaries.
10. **App lock** = PBKDF2 (310k, SHA-256) + AES-GCM over the hex secret key in IndexedDB; raw key never touches localStorage. 60-day session, re-lock on expiry/restart.
11. **Install UX**: `beforeinstallprompt` captured and triggered from our own button; mobile-only banner after onboarding/first use; iOS gets an illustrated sheet; 3-dismiss stop + 5-day snooze; desktop gets only a Settings entry (no banner by design).
12. **Permissions**: never requested without a gesture; notifications banner snoozes 4 days ("Not now"); denied state shows browser-specific re-enable instructions + "Check again".
13. **Notifications** = local only via `registration.showNotification`; badge via `setAppBadge`; no push claim anywhere in UI.
14. **QR**: generation via `qrcode` (small dep, canvas); scanning via native `BarcodeDetector` when available with paste-code fallback everywhere else (no heavy WASM scanner in v1).
15. **Single-tab lock** via Web Locks (`telepatty-main`, held for page lifetime); secondary tabs are read-only and don't run transports.
16. **CSP** via meta tag (GitHub Pages can't set headers): `script-src 'self' 'unsafe-inline'` (Nuxt payload), `connect-src wss: ws:` for relays/WebRTC, no third-party hosts; fonts self-hosted at build time via @nuxt/fonts (Vazirmatn + JetBrains Mono).
17. **Versioning**: `appVersion` = package version + git short sha, baked via `runtimeConfig.public.appVersion` (and Vite `define`); shown in Settings → About next to protocol version.
18. **Default relays**: `wss://relay.damus.io`, `wss://nos.lol`, `wss://relay.primal.net`, `wss://relay.nostr.band`, `wss://nostr.oxtr.dev` — user-editable, min-3 accepted by default.
19. **Vitest 5** with `happy-dom` + `fake-indexeddb`; `import.meta.client` statically true in tests via vitest `define` so composables are testable under a DOM.
21. **Cache-first chat UI**: Pinia does not store message arrays. Chat pages load a small `[chatId+lamport]` window from IndexedDB, append live pipeline events through the local bus, and release the window on navigation.
20. **Typecheck**: `pnpm typecheck` (vue-tsc 3 + TS 5.9) is wired into CI. The first full pass surfaced ~45 issues (strict index-access, Nuxt UI prop sizes, component generics); all identified issues were fixed in source. The local vue-tsc run could not complete inside the dev session's process limits — CI verifies the final zero-error state. The production build (`nuxt generate`) is fully green.
22. **Database upgrades stay synchronous**: a Dexie `.upgrade()` callback runs inside the `versionchange` transaction, which the browser deactivates the moment the upgrade yields to the event loop. Awaiting a dynamic `import()` (or any non-Dexie promise, including an `async` cursor callback that `.each()` never chains) makes the next cursor read throw `TransactionInactiveError: ... 'openCursor' ... The transaction is not active.` — and Dexie resolves `open()`, so the schema commits with half-written data. `backfillConversations` therefore uses static imports and a synchronous `.each()` callback; `ensureConversationSummaries()` repairs databases the bug already emptied.
23. **RTL is driven by the settings store, not `useLocaleHead` alone**: the root cause of the "Persian stays LTR" bug was that the `fa` locale definition carried no `dir` property (so `useLocaleHead` never emitted `dir="rtl"`) and `UApp` received no Nuxt-UI locale. Now: `fa` declares `dir: 'rtl'` in the i18n config; `useHtmlDir()` (single source, unit-testable) writes `<html lang>`/`dir` reactively and mirrors the language to `localStorage['tp.lang']`; an inline `<head>` script + `app/plugins/dir.client.ts` apply it BEFORE first paint on cold start (settings live in async IndexedDB); `UApp` gets the matching `@nuxt/ui/locale` (en / fa_ir, which carries `dir`) and the toast position mirrors. Directional icons flip with `rtl:rotate-180` (arrows/chevrons) or `rtl:-scale-x-100` (diagonal glyphs such as the send plane, where a 180° rotation would point them the wrong way).
24. **Bubble sides are PHYSICAL, everything else is logical**: outgoing bubbles stay on the physical right in BOTH directions (Telegram-like), defined once in `core/rtl.ts` (`BUBBLE_SIDE`, `bubbleSideClasses()` → `ml-auto/mr-0`, the grep-guard allowlist). The rest of the UI uses logical utilities (`ms/me/ps/pe/start/end/border-s/e`) so it mirrors; `app/rtl.test.ts` fails the build on new physical-direction classes. Message text uses `dir="auto"`. Those physical classes only decide the side on a box with a DEFINITE width: on a full-width `width: auto` box an auto margin collapses to 0 (CSS 2.1 §10.3.3), so the side silently came from the ambient document direction and `fa` mirrored the own bubble to the left. `MessageBubble` therefore locks its subtree (`BUBBLE_LAYOUT_DIR = 'ltr'` on the component root, whose `w-full max-w-[85%]` gives `bubbleSideClasses()`' margin a definite width, plus physical row packing); `app/rtl.test.ts` pins the dir lock, the width and the packing.
25. **Protocol versioning**: the wire `v` field is the MAJOR (still 1 — the "update the app" guard for `v > 1` is untouched); 1.1 adds `replyTo {id, senderPubkey, excerpt≤120}`, `file` (metadata header), `file_ack`/`file_cancel` payloads, all validated + sanitised in `parseEnvelope`. Legacy receivers ignore the new optional fields (the old string-only `replyTo` check simply drops the object). Dexie schema is v5 (`files` table); v5 adds no message indexes because `kind`/`fileId`/`replyExcerpt` are non-indexed fields.
26. **Files never touch relays**: the metadata envelope rides the normal outbox/router (E2EE, pending until the peer is reachable — "waiting for a direct connection"); raw chunk frames (JSON + base64, `tpFile` marker) flow ONLY over the direct WebRTC DataChannel with `bufferedAmountLowThreshold` backpressure, per-chunk indexes, receiver ACKs carrying the last contiguous chunk (resume), and final size+SHA-256 verification before the blob is stored (Dexie `files`, purged with disappearing messages/chat deletion) and ACKed ok. One file = one transferId = one message row (`fileId` references the blob); a 5 MB hard cap is enforced on send AND receive (parse-time too). Images are canvas-re-encoded (≤1600 px, quality 0.8) to strip EXIF/GPS unless the user explicitly sends the original; rendering requires content sniffing (never inline SVG/HTML), names are sanitised, blob URLs are revoked. `BlobStore` (encrypted-blob-server, e.g. Blossom) exists as an interface with `BLOB_STORE_ENABLED = false` — no adapter until the spec is verified against the codebase; the doc records what a blob server can see (IP, timing, ciphertext size).
27. **Auto-focus decision logic lives in `core/focus.ts`** (pure, tested): desktop pointer `(hover: hover) and (pointer: fine)` only, never while an editable/`<select>`/contenteditable is active, never with an open `[role=dialog]`, never during IME composition (tracked via global `compositionstart/end`), never over an existing text selection. On touch, the keyboard is only "kept" after send (composer already focused) — never opened. Type-to-focus focuses the composer during `keydown` so the character flows into it.

28. **Rooznameh is a content folder, not a CMS**: `content/rooznameh/*.md` is glob-imported with `import.meta.glob(... { query: '?raw' })` without `eager`, so every article is its own lazily-fetched asset — article text is NOT in the initial bundle and the messenger's entry chunks grow only by the small route stubs. Files starting with `_` (e.g. `_categories.md`) are never articles. `marked` + `DOMPurify` are the only new runtime deps and are reached exclusively through a dynamic `import()` inside the article pipeline (verified in `.output`: the `DOMPurify` chunk is absent from the shell's script list). No `@nuxt/content`/markdown module — it would drag its own DB/SSR machinery into an `ssr: false` app.
29. **Directive grammar is closed and tested before rendering**: a block starts with `#name` and ends at a line that is only `#`, a line that is only `--`, the next `#name`, or EOF; `---` is deliberately NOT a terminator (a markdown horizontal rule stays a horizontal rule). Unknown directives degrade to plain text with a console warning instead of swallowing content. The assembled HTML is sanitized once by DOMPurify, and media/`href` values are re-validated (`/media`-only, `http(s)`-only) AFTER markdown parsing, so an author typo cannot become an XSS or leak the reader's IP to a third party. Ad links are always re-emitted as `target="_blank" rel="sponsored noopener"`.
30. **Categories are data, validation is loud**: `_categories.md` frontmatter is the single source of ids/names/colors. An unknown `category:` does not drop the article (losing an article is worse than losing a chip) — it publishes uncategorized and logs a clear warning naming the file and the offending id. Frontmatter uses a tiny fixed-schema parser (`core/rooznameh/frontmatter.ts`) instead of a YAML dependency because the accepted keys are flat and pinned by tests.
31. **Sitemap + prerendered shells**: `nuxt.config.ts` scans the content folder at config time, writes `public/sitemap.xml` (origin from `TELEPATTY_ORIGIN`) and feeds the same article routes into `nitro.prerender.routes`, so every sitemap URL has a real `index.html`. Without that, GitHub Pages answers a deep link with the SPA fallback, i.e. HTTP 404, which crawlers will not index. The prerendered file is still the SPA shell (no article HTML), so this fixes reachability, not social previews; `content/README.md` says so plainly and names `routeRules: { '/rooznameh/**': { ssr: true } }` as the option that would — intentionally not enabled, to keep the messenger's `ssr: false` contract.
32. **The UI language is the STORED setting, never the browser**: i18n `detectBrowserLanguage` is off (`false`). With `useCookie: false` the detector was a SECOND writer — a phone whose browser is English had the locale pulled back to `en` while the stored setting kept flipping `<html lang/dir>` to `fa`/`rtl`, i.e. RTL layout with English strings (the reported "Persian is not applied on mobile"). The first-run language still comes from the browser, but only through `detectLocale()` in `core/prefs.ts`, which SEEDS the setting; `app/plugins/init.client.ts` watches `settings.language` and mirrors it into the i18n locale, so the settings page, a backup import and any future writer all move the strings as well.
33. **Live-only actions explain, they are never `:disabled`**: a file or a voice note can only travel over the OPEN direct DataChannel (raw chunks never ride relays), so with the peer offline the old `:disabled` paperclip/mic produced a dead button with no explanation. Both stay enabled and `blockLiveAction()` (`app/pages/chat/[id].vue`) distinguishes "nothing configured" (`files.disabledNoIce`) from "the other side is not online right now" (`files.bothOnlineRequired`) — re-checking `webrtc.connected(peer)` AT CLICK TIME so a stale flag can never lie; the buttons keep only a `title` hint, and paste/drag&drop go through the same gate.
34. **The header chip says online/offline and nothing else**: `ui.online && transportStatus === 'connected'`, with `connecting` only colouring the badge. Whether a message went direct, via a relay or is queued is an implementation detail the user never asked for, so `chats.direct` / `chats.relay` / `chats.offlineTransport` were deleted from both locales rather than shown.
35. **A shipped default change is a MIGRATION, not an edit**: every settings save persists the WHOLE snapshot, so virtually every existing install carries an explicit `fontSize: 15` and editing `DEFAULT_APPEARANCE` would never reach it. `migrateDefaultFontSize()` (`core/prefs.ts`) bumps exactly that legacy default once — the `tp.fontMigrated.16` marker is written BEFORE the value (a 15 chosen after the update is respected) and the migrated value is re-persisted so the next boot cannot merge 15 back — and the pre-paint boot script RENDERS the pending bump while it is still unrecorded, so the first frame after the update is already 16 instead of jumping a pixel (`core/prefs.test.ts`, `app/stores/settings.test.ts`).
36. **Sitemap and robots share ONE origin default** = the published domain `https://telepatty.ir` (`TELEPATTY_ORIGIN` overrides it for a preview/mirror). The old `rezaakt.github.io` fallback shipped sitemap URLs for a host that no longer serves the app, which is why Search Console rejected every URL; both files are now rewritten at config time (`Sitemap: <origin+baseURL>/sitemap.xml`), so they cannot drift apart, and `content/README.md` documents the exact URL to submit.
37. **An image-lightbox control only exists if its style is BOUND to the `<img>`**: the rotate/zoom/pan transform (`imgStyle`) and the wheel handler (`onWheel`) were both written but never wired — the transform sat on the computed while only the swipe feedback (`dragStyle`) was bound (to the stage), and the wheel listener had no `@wheel` anywhere. So every control "did nothing" in Rooznameh AND in chat (same component, same bug) and the overlay also rendered a stray line of pseudo-code, because the old note in the template used CSS block-comment delimiters instead of `<!-- -->` — Vue compiled it into a TEXT NODE inside the dialog. The controls are now a single `i-lucide-rotate-cw` button (+90° clockwise per press; the rotate-left and drag-rotate buttons and their `lightbox.rotateLeft`/`rotateDrag` keys are deleted), pinch zooms on touch, the mouse wheel zooms on desktop, a drag pans while zoomed, double-click/double-tap resets, and a quarter turn swaps the fit box (`max-w`↔`max-h`) so a rotated photo stays on screen. `app/components/Lightbox.test.ts` pins the binding, the 90° steps and their wrap, the single control, the absence of the stray text, wheel/pinch zoom, pan-instead-of-navigate and the reset.
38. **A locale switch must LOAD the locale's messages or the strings never change**: `@nuxtjs/i18n` v10 ships `i18n/locales/*.json` through `localeLoaders` and merges them into the composer only inside `loadLocaleMessages()`/`setLocale()` (its own `plugins/i18n.js` + `route-locale-detect.js`). Setting `i18n.locale.value = 'fa'` (the old settings page and `init.client.ts`) therefore flipped the locale with an EMPTY `fa` message table, and since `fallbackLocale: 'en'`, every `t()` rendered English while `<html dir>` (owned by the settings store through `useHtmlDir`) was already `rtl` — the reported "Persian becomes RTL but everything is still English". One helper now owns the switch: `activateLocale()` in `app/composables/useAppLocale.ts` loads first, flips second (a unit test pins that order); `plugins/init.client.ts` awaits it before mount (no English flash on cold start) and `useAppLocale()` in `app.vue` mirrors the settings store for every later writer, so the language has exactly one source and the direction/strings can never drift apart again.
39. **`sitemap.xml` / `robots.txt` are FILES, so the service worker must never answer them with the app shell**: `workbox.navigateFallback` is bound to `/` (`createHandlerBoundToURL('/')`) and the denylist only held `/^\/icons\//`, while the precache glob (`**/*.{js,css,html,png,svg,ico,woff,woff2}`) carried neither `xml` nor `txt` (`includeAssets: ['robots.txt']` did not put it in the manifest either). Opening `https://telepatty.ir/sitemap.xml` in a browser therefore got the SPA shell → the router has no such route → the app's **404 page**, which is the reported «سایت‌مپ نیست و ۴۰۴ می‌دهد» (curl/Googlebot never run the SW and always read the real XML). The glob now includes `xml`+`txt` and `/^\/sitemap\.xml$/` + `/^\/robots\.txt$/` joined the denylist; `core/pwa-config.test.ts` re-runs the config's own globs and regexes, so it fails if either half is dropped while the app's own routes keep the fallback.
40. **The sitemap has exactly TWO sources — `app/pages/**` and `content/rooznameh/*.md` — and is never edited by hand**: `@nuxtjs/sitemap` (registered in `nuxt.config.ts`, `site.url` = the published origin) owns the file, so the old config-time `public/sitemap.xml` writer and the committed file are gone (`core/pwa-config.test.ts` fails if a hand-written `public/sitemap.xml` reappears). Page routes are discovered from the page files (module default; `sitemap.exclude` is the documented way to keep one out), and articles are handed over via `sitemap.urls`, resolved at BUILD time by the pure helpers in `core/rooznameh/sitemap.ts` (`listArticles`/`sitemapUrls`/`articleRoutes`: fs read + the app's own `splitFrontmatter`, unit-tested). `sitemap.urls` was chosen over a `sources` entry on purpose — in v8 a `sources[].fetch` must be a URL served by a Nitro route, which this static SPA (no server runtime) does not have, while `sitemap.urls` runs inside the build process where the filesystem is readable. `autoLastmod` is pinned `false` and `lastmod` is the article's own `updated`/`updatedAt`/`date` frontmatter: a rebuild that changes no content must not tell crawlers every page changed. The app's rules are mirrored exactly (`draft: true`, title-less and `_`-prefixed files are skipped) because advertising a URL the app cannot render is a soft 404, and the same list feeds `nitro.prerender.routes`, so every sitemap URL answers 200 on GitHub Pages. Verified on the switch: 16 prerendered routes → `sitemap.xml` with **11 URLs** (7 page routes + 4 articles = every published markdown file), 0 build-date `lastmod`, and `sw.js` still precaches `sitemap.xml`/`robots.txt` with the `navigateFallbackDenylist` from #39 intact.
41. **The internal utility screens are excluded from the sitemap**: `/add`, `/lock` and `/onboarding` are auth-gated forms/overlays with nothing to crawl, so `sitemap.exclude` (with `/**` variants for future subroutes) removes them. The module applies `include`/`exclude` in its runtime builder against the URL PATHNAME of the final merged URL set, so the filter covers the page source and the prerender source alike, while `/`, `/friends`, `/settings`, `/rooznameh` and every article keep their URLs. `core/pwa-config.test.ts` pins both halves (the three match, the kept routes never do) and, when a build exists, asserts the generated `sitemap.xml` holds exactly 4 page routes + 4 articles — **8 URLs** (was 11). Prerendering is unaffected: those pages still answer 200, they are only kept out of the index.
42. **The header chip has THREE states, and a cold start says «در حال اتصال», never «آفلاین»**: the chip's whole contract now lives in `core/connection.ts` — `connectionState()` gives the browser's own verdict precedence (`navigator.onLine === false` is offline whatever the sockets think), then a live relay socket is `online`, an attempt still in flight is `connecting`, and `offline` is reserved for a transport that has really given up; `CONNECTION_LABEL_KEY`/`CONNECTION_BADGE_COLOR` map each state to its `chats.*` key and badge colour, and `core/connection.test.ts` pins the precedence plus the presence of the key in BOTH locales (it did not exist, so the chip had nothing but "offline" to show). Two real defects hid behind the wording: `app/layouts/default.vue` rendered `connecting` as the WORD "offline" (only the badge colour changed), and `core/nostr-transport.ts` decided its status from a SINGLE one-shot 4s check with nothing re-checking afterwards — relays still handshaking (or slower than 4s) were declared offline and the chip stayed there until the next focus/visibility `reconnect()`, i.e. the reported «اول وقتی وارد سایت میشیم باید بزنه در حال اتصال، ولی میزنه افلاین تا بشه انلاین». The transport now stays `connecting` for a 12s attempt window (the pool retries dropped sockets itself — `enableReconnect`), flips to `connected` the moment a relay answers EOSE (`oneose`) or a poll/`onclose` sees a live socket, and re-arms a poll — 3s while nothing is up, 20s once a relay is up — so the status can never freeze on a stale verdict; a socket that drops mid-session opens a FRESH window instead of flashing "offline", and a late pool callback after `stop()` can no longer resurrect a status (`if (!this.subs) return`). `ui.online` is seeded from `navigator.onLine` at boot (`app/plugins/init.client.ts`), so a phone with no network at all reads offline at once instead of "connecting".
43. **Every screen titles the browser tab, from i18n, through ONE helper**: only the two Rooznameh pages set a `<head>` (`title: t('rooznameh.title')`), so the tab read just "Telepatty" on every other screen and the request was «پیج تایتل بقیه جاها هم بزار، هم فارسی هم انگلیسی». The pattern now lives in `core/page-title.ts` — `pageTitle(page, appName)` → `<page> — <app name>`, the em-dash form the BUILD-TIME SEO tags already ship (`listHeadHtml()` writes `Rooznameh — Telepatty`), so the client tab title and the crawler-visible one cannot drift apart — and `app/composables/usePageTitle(name)` is the ONE call a page makes. The name is passed as a getter/computed, so switching the language in Settings re-titles the tab (the strings follow the locale — the old default was a static "Telepatty" and nothing re-evaluated) and dynamic names are live: `/` → `chats.title`, `/chat/<id>` → the peer's `contacts.displayName()` (the chat-list label until the contact row is loaded), `/friends` → `friends.title`, `/settings` → `settings.title`, `/settings/<section>` → `settings.sections.<id>` with a `te()` fallback to `settings.title` for a URL that names no real section (otherwise a bogus URL put the raw i18n key in the tab), `/add` → `friends.addFriend`, `/rooznameh` → the same `pageTitle()` inside its EXISTING single `useHead` (so the tab equals its static SEO title, description untouched), while `/rooznameh/<slug>` keeps the ARTICLE's own title — that IS what its build-time `<title>`/og:title tags ship, and a new post needs NO code change at all: the article page titles itself from the loaded `.md` and the posts come from a build-time glob (both pinned by grep tests in `core/page-title.test.ts`). Its loading fallback is the same «روزنامه — Telepatty» head instead of a bare «روزنامه», `/lock` → `lock.title` and `/onboarding` → `onboarding.welcome`. Those last two strings already contain the app name (`Telepatty قفل است`, `Welcome to Telepatty`), so `pageTitle()` passes them through instead of printing «Telepatty قفل است — Telepatty»; a page without a name of its own falls back to the bare app name and vice versa (no dangling dash). The app-level `useHead` in `app.vue` stays as the fallback for screens that carry no title (the error page). `core/page-title.test.ts` pins the join, the empty-half cases, the no-double-app-name case and a grep guard that turns red when a NEW `app/pages/**` file forgets to title itself.
