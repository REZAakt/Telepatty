# Changelog

## 0.1.1 — bilingual app, full personalization, Rooznameh, security
- **Package version bumped to 0.1.1** (`package.json`) — the runtime label stays `0.1.1+<git short sha>`, which `nuxt.config.ts` computes at build time from the commit being built (so the suffix after `+` is never handwritten). Shown in Settings → About and the sidebar footer.
- **The sitemap guard no longer counts with a magic number**: `core/pwa-config.test.ts` compared the generated `sitemap.xml` against a hardcoded **8** URLs (4 pages + 4 articles), so it went red on any machine that ran `pnpm generate` after the 5th article was committed — a failure that named no real regression. The article half is now read from `content/rooznameh/` with the same pure `listArticles()` helper the config hands to `sitemap.urls`, and every expected `/rooznameh/<slug>` URL is still asserted individually (10 URLs today: 4 page routes + 6 articles). The exclude / no-hand-written-sitemap / PWA halves are untouched.
- **The 1.1 release article is user-facing now**: `content/rooznameh/telepatty-1-1-update.md` was a feature list; it is now a plain-language announcement (bilingual interface, app-wide personalization including the dark/light theme, the Rooznameh section, message security, security hardening and the bug-fix round) with a fresh date, description and tags. Same slug/URL, same blocks (`#media`, `#callout`, `#quote`, `#ad`, `#source`).
- **The internal utility screens are out of the sitemap** — `/add`, `/lock` and `/onboarding` only render a form/overlay (auth-gated, no crawlable content), so indexing them was pure noise. They are now filtered by `sitemap.exclude` (`/add`, `/lock`, `/onboarding` plus `/**` variants that guard future subroutes); the module applies `include`/`exclude` to the URL **pathname of the final merged URL set**, so both the page source and the prerender source are covered, while `/`, `/friends`, `/settings`, `/rooznameh` and every article are untouched. `core/pwa-config.test.ts` pins both halves (the three match, the kept routes never do) and — when a build is present — asserts the generated `sitemap.xml` holds exactly the expected set. Result at the time: **8 URLs** (4 page routes + 4 articles), down from 11 — the article half of that guard now follows `content/rooznameh/` (see the count note above), so it reads **10 URLs** (4 page routes + 6 articles) today.
- **The sitemap is now generated by `@nuxtjs/sitemap` — nothing about it is written by hand any more.** `public/sitemap.xml` (a file the config used to rewrite) is **deleted**; the module writes `sitemap.xml` during `pnpm generate` from two automatic sources: the Nuxt page routes (`output/public/sitemap.xml` now lists `/`, `/add`, `/friends`, `/lock`, `/onboarding`, `/rooznameh`, `/settings` as well) and the articles, handed over by `sitemap.urls` → the new pure `core/rooznameh/sitemap.ts` helpers, which read `content/rooznameh/*.md` through the app's own frontmatter parser. Dropping a markdown file in `content/rooznameh/` is now the **only** step needed for an article to appear (and deleting it removes the URL); `draft: true`, title-less and `_`-prefixed files never appear. `lastmod` is the article's own date (`updated`/`updatedAt` beating `date`) — `autoLastmod` is pinned `false`, so a rebuild with no content change can never claim every page changed. The PWA fix is untouched *and verified* in the new build: `sitemap.xml`/`robots.txt` stay precached (`xml`+`txt` in `workbox.globPatterns`) and denylisted from `navigateFallback`, so a browser opening `https://telepatty.ir/sitemap.xml` still gets the real XML. `core/rooznameh/sitemap.test.ts` adds a temp article to `content/`, asserts its URL shows up with its frontmatter date, and removes it again; `core/pwa-config.test.ts` pins the wiring (module registered, `autoLastmod: false`, `sitemapUrls()` used, no `public/sitemap.xml`). Last build: **11 URLs** (7 page routes + 4 articles) = every published markdown file, none with a build-date `lastmod`.
- **`https://telepatty.ir/sitemap.xml` no longer answers 404 in a browser.** The file was always on the server (curl and Googlebot read the real XML), but the PWA **service worker** answers every navigation with the SPA shell (`workbox.navigateFallback` → `createHandlerBoundToURL('/')`), and only `/icons/` was denylisted — so opening the sitemap in a browser served `index.html`, the SPA router found no `/sitemap.xml` route and rendered the app's 404 page. `sitemap.xml`/`robots.txt` are now **precached** (`xml`+`txt` added to the workbox `globPatterns`, which also finally caches `robots.txt` — `includeAssets` alone did not) and **denylisted** (`/^\/sitemap\.xml$/`, `/^\/robots\.txt$/`) from the navigation fallback, while the app's own routes keep it. `core/pwa-config.test.ts` re-runs the config's own globs and regexes, so the guard fails if either half is dropped.
- **The image lightbox works now — in Rooznameh AND in chat (one component, one bug).** Root cause: `imgStyle` (the image's rotate/zoom/pan transform) was computed but never bound to the `<img>` — only the swipe feedback was bound, to the stage — so every control changed state and the pixels never moved; `onWheel` was dead code with no `@wheel` listener either. The template also carried a raw CSS-style block-comment note (asterisk-slash delimiters, not an HTML comment) that Vue compiled into a **text node inside the overlay** — that stray line of code beside the image is gone. Controls are now: ONE rotate button (top-left, `i-lucide-rotate-cw`) that turns the image **90° clockwise per press** (rotate-left and drag-rotate buttons, plus their `lightbox.rotateLeft`/`lightbox.rotateDrag` keys, are deleted), **pinch** zoom on touch, **mouse-wheel** zoom on desktop, drag-to-pan while zoomed, and double-click/double-tap to reset the view. A quarter turn swaps the fit box (`max-w`↔`max-h`) so a rotated photo stays on screen. `app/components/Lightbox.test.ts` pins the binding, the 90° steps and their wrap, the single control, the missing stray text, wheel/pinch zoom, pan-instead-of-navigate and the reset.
- **Persian strings are really applied now.** The locale used to be flipped with `i18n.locale.value = 'fa'` alone (`plugins/init.client.ts` and the settings page), but `@nuxtjs/i18n` v10 delivers locale JSON through `localeLoaders` and merges it into the composer only inside `loadLocaleMessages()`/`setLocale()` — so `fa` had **no messages** and every `t()` resolved through `fallbackLocale: 'en'`: RTL layout, English words, on cold start and on every switch, phone and desktop alike. New `app/composables/useAppLocale.ts` (`activateLocale()`) **loads a locale's messages and only then switches**; the cold start in `init.client.ts` awaits it before mount (no English flash) and `useAppLocale()` in `app.vue` mirrors the settings store for every later writer (settings page, backup import), so `<html dir>` and the strings can never drift apart again. The settings page now only writes the store, and `app/composables/useAppLocale.test.ts` pins the load-before-flip order.
- Sending a file or a voice note while the other person is offline explains itself again: the paperclip and the mic are no longer `:disabled` (a dead button explains nothing), and the click runs the same live gate the send path uses (`blockLiveAction()` in `app/pages/chat/[id].vue`) — it distinguishes “nothing configured” (no ICE/relay) from “the other side is not online right now” and toasts the matching message. Paste and drag&drop go through the identical gate instead of the old no-ICE wording.
- The header chip says **only** «آنلاین / آفلاین» (`chats.online` / `chats.offline`): it no longer leaks how the transport is carried. `chats.direct`, `chats.relay` and `chats.offlineTransport` («مستقیم» / «از طریق رله» / «آفلاین — پیام‌ها صف می‌شوند») are deleted from both locales. Online = the browser has a network AND the relay socket is up.
- **Persian is really applied on phones now.** Root cause: `detectBrowserLanguage` was still on (`useCookie: false`), so a phone whose browser is English had the i18n locale re-detected as `en` while the stored setting kept flipping `<html dir>` to `rtl` — RTL layout, English strings. Browser detection is off (`detectBrowserLanguage: false`; the first-run language is still seeded from the browser by `core/prefs` `detectLocale`), and `init.client.ts` now watches `settings.language` and mirrors it into the i18n locale, so every writer (settings page, backup import) flips the strings too.
- The shipped default font size is **16 px** instead of 15 (`core/theme.ts`, `main.css`, the pre-paint boot script) — and because every save persists the whole snapshot, existing installs carried an explicit `fontSize: 15` and would never have seen the new default: `migrateDefaultFontSize()` in `core/prefs.ts` bumps exactly that legacy default ONCE (`tp.fontMigrated.16` marker, written BEFORE the value) and re-persists to IndexedDB, so a 15 chosen deliberately after the update is respected; the boot script renders the still-unrecorded bump, so the first frame after the update is already 16 instead of jumping a pixel. `app/stores/settings.test.ts` and `core/prefs.test.ts` pin both halves.
- SEO / Google Search Console: the build-time sitemap and the canonical origin point at the published domain `https://telepatty.ir` (`TELEPATTY_ORIGIN` default was the stale `https://rezaakt.github.io`, so every URL in `public/sitemap.xml` named a host that no longer serves the app). `nuxt.config.ts` now also regenerates `public/robots.txt` at build time with the matching `Sitemap: <origin><baseURL>/sitemap.xml` line, so the two files can never drift apart again (submit exactly that URL in Search Console).
- Chat bubbles now follow the theme instead of a hardcoded pale green: the OWN bubble background is the live accent mixed into the app background (`color-mix(accent 25%, --tp-bg)`) with `--ui-text` on top — dark in dark mode, light in light mode — while the peer's bubble keeps its accent-over-panel tint. The `#d9f2dc`/`#0d3b1e` pair (and the matching `text-dimmed` override that only existed for it) is gone.
- Persian (RTL) chat layout fix: own messages now sit on the physical RIGHT in `fa` exactly like in `en`. Root cause: a flex row packs along its main axis, and `row`/`row-reverse` both start at that row's inline start, so `flex-row-reverse` mirrored with `<html dir="rtl">`; the physical side classes could not compensate because they sat on a full-width `width: auto` box, where an auto margin collapses to 0 (CSS 2.1 §10.3.3). `MessageBubble` now renders its rows inside a physically locked subtree (`BUBBLE_LAYOUT_DIR = 'ltr'` in `core/rtl.ts`, applied to the component root, whose `w-full max-w-[85%]` gives `bubbleSideClasses()`' auto margin a definite width to resolve against), while every bubble keeps `dir="auto"` so Persian text still reads right-to-left. `app/rtl.test.ts` pins all three halves (dir lock, definite width, physical row packing).
- The header brand mark is the real app icon (`public/icons/icon-512.png`, base-path aware through the new `useAppIcon()` composable) instead of the `▮▮` glyph placeholder — in the app header and on the onboarding screen, matching the favicon/PWA icon.
- Language switch now flips the whole layout instantly: the `fa` i18n locale declares `dir: 'rtl'`, `<html lang>`/`dir` are driven reactively from the language setting (`useHtmlDir`), Nuxt UI internals follow via `UApp :locale`, toasts mirror sides, and a pre-paint inline script + early plugin apply the stored direction before first paint (no LTR flash). Sidebar/back/send icons flip in RTL; message bubbles keep the Telegram-like physical side (outgoing right) in both directions via a single `core/rtl` constant; `app/rtl.test.ts` mounts the shell, switches fa↔en and asserts `dir`/`lang`/sidebar side, plus a grep guard that fails on new physical-direction classes (`ml/mr/pl/pr/left/right/…`).
- Desktop auto-focus: `core/focus.ts` decision logic + `useAutoFocus` composable + `v-autofocus-desktop` directive (desktop pointers only — `(hover: hover) and (pointer: fine)`). The composer focuses on chat open, after send, after any dialog/sheet/lightbox closes, on window focus/visibility, after Reply, and on empty-space clicks; type-to-focus drops printable characters (Persian-safe, IME-aware) into the composer; primary inputs on the chat list, lock, onboarding and backup screens focus on mount. Mobile never gets a forced keyboard (after send the keyboard only stays open if it was open).
- Replies: `replyTo` in the envelope is now `{ id, senderPubkey, excerpt ≤120 }` inside the E2EE envelope (protocol minor 1.1, legacy string refs ignored, unknown major versions still trigger the update guard); composer reply bar, quoted block on bubbles with tap-to-jump (loads older pages by cursor, brief highlight, "Original message unavailable" fallback), swipe-left-to-reply with Pointer Events + `touch-action: pan-y` (64 px trigger, haptic tick, spring back), hover Reply button + long-press menu on mobile, and Arrow Up in an empty composer cycles the reply target (Arrow Down back, Esc cancels, IME/caret-safe).
- File sending (hard 5 MB cap, enforced on send and receive): images are downscaled to ≤1600 px and re-encoded (strips EXIF/GPS; "send original" available with a metadata warning); videos/any type pass through if ≤5 MB. Metadata envelope rides the normal outbox/router; bytes stream over the direct WebRTC DataChannel only (16 KB chunks, backpressure via `bufferedAmountLowThreshold`, per-chunk index, resume from the receiver's last confirmed chunk, SHA-256 + size verification, ACK/receipt, cancel/retry, progress bars). Without a direct connection the file message stays pending ("waiting for a direct connection") — relays never store files, and the UI says so. Attach button, clipboard paste, drag-and-drop, multi-file preview with caption; image/video bubbles + lightbox + file cards; receiver auto-downloads images from friends (setting), everything else tap-to-download; content sniffing before rendering (no inline SVG/HTML), sanitized file names, blob URLs revoked, `media-src 'self' blob:` in the CSP. New Dexie v5 `files` table (purged with disappearing messages and chat deletion; Storage settings show usage + delete action; backups include files optionally with a size warning). A `BlobStore` interface for a future encrypted blob server ships disabled and unimplemented (no adapter until the spec is verified).
- Tests: focus decision logic, reply excerpts/sanitisation/target cycling, swipe threshold/intent logic, chunking + reassembly + resume + hash/size rejection, name sanitisation + sniffing, v5 migration (files table), purge of files with disappearing messages, wire-format round-trips for `replyTo`/`file`/`fileAck`, and the RTL shell test.
- Rooznameh (روزنامه): new magazine section at `/rooznameh`, second item in the main nav. Content lives in the repo as markdown (`content/rooznameh/*.md` + `_categories.md`), so articles are static assets and are fetched **on demand, only when a magazine route is opened** — `marked` + `DOMPurify` plus the article loader live in a lazy chunk and are not part of the messenger's initial payload (verified against `.output`: no `DOMPurify` in the shell's script list). Block directives inside the body (`#text`, `#media`, `#ad`, `#quote`, `#callout`, `#source`) are parsed by `core/rooznameh/directives.ts` (pure + tested) and every rendered fragment is sanitized; a markdown `---` stays a horizontal rule. Category chips + search (title/description/tags), responsive card grid, reading time, "newest 5" side column, article page with reading-progress bar, Web Share API (copy-link fallback), related-by-category, prev/next, per-article canonical/OG/Twitter head, an `#ad` block reused as a non-intrusive sidebar slot, and an image lightbox with reserved aspect ratios (no layout shift) and a missing-file placeholder instead of a broken image. Build-time sitemap (`public/sitemap.xml`) plus a prerendered shell per article route, so GitHub Pages answers 200 (not the 404 fallback) for every sitemap URL — `ssr:false` still means the HTML contains the app shell, not the article text, which is documented honestly in `content/README.md` along with the `routeRules` option that would fix social previews. i18n labels in fa + en, RTL/LTR via logical utilities. New tests: directive parser (all block types, all terminators, malformed input), frontmatter parsing/validation, and category validation (missing/duplicate/unknown ids + sorted/related/newest helpers).

- Reworked chat storage around local-first conversation summaries, paged message windows, processed Nostr wrap dedupe, and incremental sync checkpoints.
- Fixed the v4 migration crashing with `TransactionInactiveError: Failed to execute 'openCursor' on 'IDBObjectStore': The transaction is not active.` (dynamic `import()` / async cursor callback inside the upgrade transaction) and added a startup self-heal that rebuilds conversation summaries for databases the failed migration left behind.

- Added storage repair for rebuilding conversation summaries, seeded performance data via `pnpm seed`, and tests for list reads, unread counters, paging, processed events, and migration backfill.
- Improved chat UI behavior: mobile bottom navigation hides inside chats, desktop composer focuses automatically, route loading shows the accent progress line, and reply bubbles show Telegram-style context.
- Fix round for the 10 reported bugs, all with their root cause removed: **presence** no longer freezes on “unknown” (`ui.directPeers` is reactive and the open chat re-checks the live channel every 5 s, re-offering when it dropped); the **chat list** sorts by the newest message (`compareConversations`); up to **3 chats can be pinned** (`MAX_PINNED_CHATS`/`canPinChat`/`togglePin`, pinned first, secondary-click/long-press context menu); **Settings and Rooznameh follow the selected theme** — `--tp-accent` now resolves to the live `--ui-primary` token instead of a hardcoded matrix green (`main.css`, the pre-paint script, the QR code), and choosing another primary color clears a stale preset accent; the **“storage is best-effort”** indicator (state, toast and its unused i18n key) is gone; **three distinct synthesized sounds** (incoming message / outgoing tick / system alert) replace the single shared beep; the **PWA update action is reachable from Settings → Install** and the toast, through one shared updater (`useInstall.registerUpdate` + `applyUpdate`, registered by `UpdateWatcher`); the image **lightbox** gained rotate/zoom; **directional icons flip in RTL** (settings list chevrons, back arrows, Rooznameh prev/next) with the diagonal send glyph *mirrored* (`rtl:-scale-x-100`) instead of rotated 180°; and a second tab gets a full-screen **TabGuard** overlay until it becomes the main tab again.
- Tests: `core/theme.test.ts` pins the new accent contract (explicit override wins, otherwise the live Nuxt UI primary token) and the `app/rtl.test.ts` grep guard is green again.
- The **calendar and digit settings work now** — `core/format.ts` builds the locale tag by PINNING both axes (`-u-ca-persian|gregory-nu-arabext|latn`) instead of only appending a suffix when a switch was ON. Root cause: `fa-IR` already defaults to the Persian calendar *and* to arabext digits, so with the app in Persian, Jalali↔Gregorian and Persian↔Latin produced **byte-identical** output everywhere (chat date separators, message stamps, the chat list, Rooznameh) — the appended `-u-ca-persian`/`-nu-arabext` changed nothing. The new `formatNumericDate()` renders a compact `YYYY/MM/DD` from `formatToParts()` (same read order in both languages) and the Persian-calendar era ("1402 AP") is stripped; `core/format.test.ts` pins both axes in both languages.
- **Rooznameh list is scannable**: article cards (and the "newest" sidebar on `/rooznameh`) show a numeric date and no longer repeat the reading time — reading time lives on the article page, as before.
- **Rooznameh content**: the welcome article (`hello-rooznameh`) is a much longer, friendlier introduction (why the magazine exists, what gets published, how to read it, how to write one, a closing word) and a **new guide**, `add-friends` (Persian, with the same guide in English at the end), walks through invitations (QR / invite link / friend code), adding someone, the fingerprint check, accepting–declining–ignoring–blocking a request and the first chat — with a matching `public/media/cover-friends.svg`.



## 0.1.0 — initial release

- Identity: browser keypair, nsec backup/restore, optional passphrase app lock (AES-GCM + PBKDF2), 60-day session re-lock.
- Friends: invite link (hash-fragment) / QR / friend code, friend requests with rate limiting, fingerprints, block/unblock, rename/pin/mute/archive.
- Messaging: NIP-59 gift-wrapped envelopes over Nostr (NIP-40 expiration), WebRTC DataChannel fast path with Nostr signaling, outbox with exponential backoff, delivery/read receipts, Lamport ordering, disappearing messages.
- PWA: installable, offline app shell, prompt-based updates, mobile install banner + iOS sheet, single-tab lock.
- Permissions Center, encrypted backups (v2 schema, tested migration), chat export, fa/en i18n with RTL and Jalali dates.
